# 测试环境部署指南

## 概述

本文档说明如何将本地开发完成的 vendor 接入公司测试环境。以智谱 BigModel 接入为例。

## 前置检查清单

### ✅ 本地开发配置恢复

在提交代码前，需要将本地开发时修改的配置恢复为测试环境标准配置：

1. **frontend/vite.config.js** - 前端代理端口
   ```javascript
   // ❌ 本地开发
   target: 'http://127.0.0.1:8000'
   
   // ✅ 测试环境
   target: 'http://127.0.0.1:3081'
   ```

2. **移除调试代码** - 删除临时添加的调试日志、注释等

3. **确认数据库配置** - 测试环境使用服务器共享 PostgreSQL，不使用本地 docker-compose.local.yml

### 📦 需要提交的文件

**核心业务代码**（以智谱为例）：
```bash
# 新增的 vendor 文件
backend/bigmodel_client.py                    # 实时查询客户端
backend/ingest/adapters/bigmodel_adapter.py   # 入库适配器

# 修改的注册文件

backend/main.py                               # VENDOR_DISPATCH 注册
backend/ingest/adapters/__init__.py           # ADAPTERS 注册
backend/.env.example                          # 环境变量示例（可选）
```

### 🚫 不要提交的文件

**本地开发专用文件**：
```bash

backend/debug_*.py            # 调试脚本
backend.pid                   # 进程文件

```

**文档文件**（可选择性提交到 docs/）：


## 部署流程

### 1. 提交代码到 GitLab

```bash
# 添加核心文件
git add backend/bigmodel_client.py \
        backend/ingest/adapters/bigmodel_adapter.py \
        backend/config/vendors.json \
        backend/main.py \
        backend/ingest/adapters/__init__.py

# 提交
git commit -m "feat(bigmodel): 接入智谱 BigModel 供应商

- 新增 bigmodel_client.py 实时查询客户端
- 新增 bigmodel_adapter.py 入库适配器
- 在 VENDOR_DISPATCH 注册 bigmodel
- 支持 Playwright 扫码登录
- 自动 cron 每日 03:00 入库

Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>"

# 推送到远端
git push
```

### 2. 服务器部署

```bash
# SSH 到测试服务器
ssh your-test-server

# 进入项目目录
cd /data/llm-usage-dashboard

# 拉取最新代码
sudo git pull

# 处理 vendors.json 冲突（如果有）
# 根据 CLAUDE.md：永远使用远端版本
sudo git checkout --theirs backend/config/vendors.json
# 然后手动合并新 vendor 配置

# 重建并启动后端
sudo docker compose up -d --build backend

# 查看日志确认启动正常
sudo docker compose logs -f backend
```

### 3. Playwright 登录（针对需要登录的 vendor）

**适用于**: kimi, apevon, blueshirt, bigmodel 等无公开 API 的供应商

#### 智谱登录流程

智谱使用 **微信扫码登录**，session 保存在 `config/sessions/bigmodel_cn.json`

**方法1: API 触发登录**
```bash
curl -X POST http://your-test-server:3081/api/vendors/bigmodel/login
```

**方法2: 前端触发**
1. 访问面板 → 找到智谱供应商卡片
2. 点击"登录"按钮
3. 等待浏览器弹出

**登录步骤**：
1. Playwright 自动打开浏览器到 `https://bigmodel.cn/login`
2. 使用手机微信扫码登录
3. 登录成功后 URL 跳转到 `/console/overview`
4. Session 自动保存到 `config/sessions/bigmodel_cn.json`
5. 浏览器自动关闭

#### 验证登录状态

```bash
# 检查 session 状态
curl http://your-test-server:3081/api/vendors/bigmodel/session

# 成功返回示例：
# {
#   "status": "logged_in",
#   "vendor_type": "bigmodel",
#   "file": "bigmodel_cn.json"
# }

# 未登录返回示例：
# {
#   "status": "not_logged_in",
#   "vendor_type": "bigmodel",
#   "message": "未找到 session 文件"
# }
```

### 4. 数据回填

```bash
# 回填最近 30 天数据（推荐）
docker compose exec backfill python -m ingest.backfill --vendors=bigmodel --days=30

# 回填最近 90 天数据
docker compose exec backfill python -m ingest.backfill --vendors=bigmodel --days=90

docker compose exec backfill python -m ingest.backfill \
  --vendors=bigmodel \
  --start=2026-06-01 \
  --end=2026-07-15
```

### 5. 验证数据

#### 检查入库状态

```bash
# 查看所有 vendor 入库状态
curl http://your-test-server:3081/api/ingest/state

# 筛选智谱状态
curl http://your-test-server:3081/api/ingest/state | \
  jq '.[] | select(.vendor_id=="bigmodel")'

# 返回示例：
# {
#   "vendor_id": "bigmodel",
#   "last_ingested_date": "2026-07-14",
#   "updated_at": "2026-07-15T03:00:00Z"
# }
```

#### 检查数据质量

```bash
# 查看智谱用量数据
curl "http://your-test-server:3081/api/vendors/bigmodel/usage?start=2026-07-01&end=2026-07-15"

# 查看入库任务历史
curl "http://your-test-server:3081/api/ingest/runs?vendor_id=bigmodel&limit=20"

# 查看失败的任务
curl "http://your-test-server:3081/api/ingest/runs?vendor_id=bigmodel&status=failed"
```

#### 前端验证

1. 访问面板首页 `http://your-test-server`
2. 在 Overview 页面查看智谱卡片是否出现
3. 点击卡片进入详情页，查看数据是否正常
4. 检查模型列表、token 统计、成本统计

## 自动调度

接入后会自动生效：

| 时间 | 任务 | 说明 |
|---|---|---|
| CST 03:00 | 智谱入库 | 与其他 vendor 一起串行入库 |
| 前端 | 自动显示 | vendor 列表自动显示智谱卡片 |
| Overview | 自动汇总 | 全局统计自动包含智谱数据 |

**调度逻辑**：
- 从 `last_ingested_date + 1` 拉到昨天
- 智谱属于 T+1 延迟 vendor（今天的数据明天凌晨才出账）
- 失败后自动重试 4 次（立刻 / 5min / 30min / 1h）
- 重试用尽后推送飞书告警

## 故障排查

### 查看日志

```bash
# 查看调度日志
docker exec backend tail -f /app/data/logs/scheduler.log

# 查看后端实时日志
docker compose logs -f backend

# 查看最近 100 行日志
docker compose logs --tail=100 backend
```

### 常见问题

#### 1. "X 供应商有未入库的天"

**原因**: vendor 首次入库日期到最后入库日期之间有缺失的天

**解决方法**:
```bash
# 方法1: 前端 vendor 详情页点击"更新"按钮

# 方法2: API 手动触发
curl -X POST http://your-test-server:3081/api/ingest/vendors/bigmodel/trigger \
  -H "Content-Type: application/json" \
  -d '{"start": "2026-07-01", "end": "2026-07-14"}'
```

#### 2. "上次同步"很久没动

**原因**: zombie 任务卡在 `running` 状态

**解决方法**:
```bash
# 重启 backend 会自动清理 >2h 的 running 任务
sudo docker compose restart backend

# 或手动标记失败
docker exec backend psql postgresql://user:pass@localhost:5432/llm_usage -c \
  "UPDATE llm_usage_dashboard.vendor_ingest_run 
   SET status='failed' 
   WHERE vendor_id='bigmodel' AND status='running'"
```

#### 3. Session 失效（Playwright vendor）

**现象**: 前端显示"未登录"，API 返回 401/403

**解决方法**:
```bash
# 重新登录
curl -X POST http://your-test-server:3081/api/vendors/bigmodel/login

# 或前端点击"登录"按钮
```

#### 4. 数据为 0 或缺失

**可能原因**:
- 上游 T+1 延迟（今天的数据明天才出）
- 上游接口限流或异常
- Session 失效未登录

**排查步骤**:
```bash
# 1. 查看 scheduler.log 确认任务是否执行
docker exec backend tail -f /app/data/logs/scheduler.log

# 2. 查看入库任务状态
curl "http://your-test-server:3081/api/ingest/runs?vendor_id=bigmodel&limit=5"

# 3. 检查 session 状态
curl http://your-test-server:3081/api/ingest/state | jq '.[] | select(.vendor_id=="bigmodel")'

# 4. 手动触发测试
curl -X POST http://your-test-server:3081/api/ingest/vendors/bigmodel/trigger \
  -H "Content-Type: application/json" \
  -d '{"start": "2026-07-14", "end": "2026-07-14"}'
```

#### 5. 重试失败任务

```bash
# 查看失败的 run_id
curl "http://your-test-server:3081/api/ingest/runs?vendor_id=bigmodel&status=failed"

# 重试指定任务
curl -X POST http://your-test-server:3081/api/ingest/runs/{run_id}/retry
```

## 重要约束

### 1. vendors.json 冲突处理

根据 CLAUDE.md 说明：

> 服务器 `.env` 凭据是手动配的：git pull 时如果 `vendors.json` 冲突永远 `git checkout --theirs` 远端版本

```bash
# 如果 git pull 时 vendors.json 冲突
sudo git checkout --theirs backend/config/vendors.json

# 然后手动编辑，把新 vendor 配置加进去
sudo vim backend/config/vendors.json
```

### 2. Session 有效期

- kimi, apevon, blueshirt, bigmodel 的 session 可能定期失效
- 失效后需要重新扫码/验证码登录
- 建议定期检查登录状态

### 3. 网络要求

- 测试服务器需要能访问上游 vendor 的 API（如 `https://bigmodel.cn`）
- Playwright 首次启动需要下载浏览器，确保网络通畅
- 如使用代理，需配置 Playwright 代理设置

### 4. 权限要求

```bash
# config/sessions/ 目录需要容器可写
sudo chmod 755 backend/config/sessions

# session 文件会自动创建，无需手动创建
```

### 5. 调度器单 worker 假设

- **当前 scheduler 假设单 worker**
- 多 worker 会重复跑 cron
- 如需多 worker，需要改造为 PG advisory lock

2. ✅ 提交核心业务代码，排除本地开发文件
3. ✅ 服务器 git pull + docker compose 重启
4. ✅ Playwright 登录（如需要）
5. ✅ 数据回填验证
6. ✅ 自动调度生效
