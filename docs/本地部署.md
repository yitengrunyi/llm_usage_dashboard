# 本地部署指南

本文档帮助你在**自己的电脑**上运行这个项目，使用**你自己的供应商账号**查看数据。

---

## 📋 前置条件

### 必需软件

1. **Docker Desktop**
   - Mac: https://www.docker.com/products/docker-desktop/
   - Windows: https://www.docker.com/products/docker-desktop/
   - 安装后启动 Docker Desktop

2. **Git**
   - Mac: 自带，或 `brew install git`
   - Windows: https://git-scm.com/download/win

3. **PostgreSQL**（可选）
   - 方式 A: Docker 运行（推荐）
   - 方式 B: 本地安装 https://www.postgresql.org/download/

4. **Node.js**（前端需要）
   - 版本: 16+ 
   - 下载: https://nodejs.org/

## 🚀 快速开始（5 步）

### 步骤 1: 克隆项目

```bash
# 克隆代码
git clone <your-repo-url>
cd llm_usage_dashboard

# 或者如果你已经有代码
cd /path/to/llm_usage_dashboard
```

### 步骤 2: 启动数据库

**方式 A: 使用 Docker（推荐）**

```bash
# 创建 docker-compose.local.yml
cat > docker-compose.local.yml << 'EOF'
services:
  postgres:
    image: postgres:15
    container_name: llm_usage_db
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: llm_usage
    ports:
      - "5432:5432"
    volumes:
      - ./data/postgres:/var/lib/postgresql/data
    restart: unless-stopped
EOF

# 启动数据库
docker compose -f docker-compose.local.yml up -d postgres
```

**方式 B: 使用本地 PostgreSQL**

```bash
# Mac
brew install postgresql@15
brew services start postgresql@15

# 创建数据库
createdb llm_usage
```

### 步骤 3: 配置后端

```bash
cd backend

# 1. 复制配置文件
cp .env.example .env

# 2. 编辑 .env（填入你自己的凭据）
vim .env  # 或用任何编辑器打开
```

**最小配置（只配置你有账号的供应商）**：

```bash
# ===== 数据库配置（必填） =====
DB_HOST=localhost
DB_PORT=5432
DB_NAME=llm_usage
DB_USER=postgres
DB_PASSWORD=postgres

# ===== 供应商凭据（按需填写） =====

# 1. OpenAI（如果你有 Admin API key）
# OPENAI_API_KEY=sk-admin-xxxx

# 2. 腾讯云（如果你有账号）
# TC_SECRET_ID=AKIDxxxx
# TC_SECRET_KEY=xxxx

# 3. 网宿（如果你有账号）
# WANGSU_ACCESS_KEY=xxxx
# WANGSU_SECRET_KEY=xxxx

# 4. 火山方舟（如果你有账号）
# VOLCENGINE_ACCESS_KEY=xxxx
# VOLCENGINE_SECRET_KEY=xxxx

# 5. UCloud（如果你有账号）
# UCLOUD_PUBLIC_KEY=xxxx
# UCLOUD_SECRET_KEY=xxxx
# UCLOUD_PROJECT_ID=xxxx

# 6. Road2All（如果你有账号）
# ROAD2ALL_USERNAME=your_username
# ROAD2ALL_PASSWORD=your_password

# 7. Nulls（如果你有账号）
# NULLS_USERNAME=your_username
# NULLS_PASSWORD=your_password

# 8. 智谱 BigModel（后续登录获取）
# BIGMODEL_TOKEN=

# ===== 可选配置 =====
# 飞书告警（不填则只输出日志）
# FEISHU_WEBHOOK_URL=

# 外部触发鉴权（本地开发可以不填）
# INGEST_TOKEN=
```

**3. 安装依赖**

```bash
# 创建虚拟环境（推荐）
python3 -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate

# 安装依赖
pip install -r requirements.txt

# 安装 Playwright 浏览器（用于 Kimi/Apevon/Blueshirt/智谱登录）
python -m playwright install chromium
```

**4. 初始化数据库**

```bash
# 运行数据库迁移
cd backend
python -c "
from ingest.db import Base, engine
from ingest import models  # 导入模型
Base.metadata.create_all(engine)
print('✅ 数据库表创建完成')
"
```

**5. 启动后端**

```bash
# 在 backend 目录下
python -m uvicorn main:app --reload --port 8000
```

后端现在运行在：http://localhost:8000

### 步骤 4: 配置前端

**打开新的终端**：

```bash
cd frontend

# 安装依赖
npm install

# 启动开发服务器
npm run dev
```

前端现在运行在：http://localhost:5173（或 http://localhost:3000，看输出）

### 步骤 5: 登录供应商（需要登录的）

某些供应商需要浏览器登录（Kimi/Apevon/Blueshirt/智谱）：

**方式 A: 通过 API**

```bash
# Kimi
curl -X POST http://localhost:8000/api/vendors/kimi/login

# 智谱 BigModel
curl -X POST http://localhost:8000/api/vendors/bigmodel/login

# Apevon
curl -X POST http://localhost:8000/api/vendors/apevon/login

# Blueshirt
curl -X POST http://localhost:8000/api/vendors/blueshirt/login
```

**方式 B: 通过前端**

1. 访问 http://localhost:5173
2. 进入对应供应商的详情页
3. 点击"登录"按钮
4. 在弹出的浏览器中完成登录

登录完成后，session 会保存到 `backend/config/sessions/` 目录。

## 📊 拉取数据

### 方式 1: 手动触发（推荐用于测试）

**通过 API：**

```bash
# 拉取某个供应商最近 7 天的数据
curl -X POST http://localhost:8000/api/ingest/vendors/bigmodel/trigger \
  -H "Content-Type: application/json" \
  -d '{"start": "2026-07-06", "end": "2026-07-12"}'

# 查看拉取状态
curl http://localhost:8000/api/ingest/runs?vendor_id=bigmodel&limit=5
```

**通过前端：**

1. 访问供应商详情页
2. 点击"更新数据"按钮
3. 选择日期范围

### 方式 2: 批量回填

```bash
cd backend

# 回填单个供应商最近 30 天
python -m ingest.backfill --vendors=bigmodel --days=30

# 回填所有已配置的供应商
python -m ingest.backfill --vendors=all --days=30

# 回填指定日期范围
python -m ingest.backfill --vendors=bigmodel \
  --start=2026-06-01 \
  --end=2026-07-12
```

### 方式 3: 启动自动调度（可选）

如果你希望每天自动拉取数据：

后端默认会启动 APScheduler，每天凌晨 3:00 自动拉取。

你可以调整调度时间：

```bash
# 编辑 backend/ingest/scheduler.py
# 找到 cron 配置，修改时间
```

## 🔍 查看数据

### 1. 前端 Dashboard

访问：http://localhost:5173

- **Overview 页面**：查看所有供应商的汇总数据
- **Vendor 详情页**：查看单个供应商的明细

### 2. API 直接查询

```bash
# 查看所有供应商列表
curl http://localhost:8000/api/vendors | jq .

# 查看某个供应商的数据
curl "http://localhost:8000/api/vendors/bigmodel/usage?start=2026-07-01T00:00:00%2B08:00&end=2026-07-12T23:59:59%2B08:00" | jq .

# 查看 Overview
curl "http://localhost:8000/api/overview?start=2026-07-01T00:00:00%2B08:00&end=2026-07-12T23:59:59%2B08:00" | jq .
```

### 3. 数据库直接查询

```bash
# 连接数据库
psql postgresql://postgres:postgres@localhost:5432/llm_usage

# 查看所有供应商的数据
SELECT vendor_id, usage_date, cost_cny, total_tokens
FROM vendor_usage_daily
ORDER BY usage_date DESC
LIMIT 20;

# 查看某个供应商的模型明细
SELECT model, SUM(cost_native) as total_cost, SUM(total_tokens) as total_tokens
FROM vendor_model_usage_daily
WHERE vendor_id = 'bigmodel'
GROUP BY model
ORDER BY total_cost DESC;

# 查看入库状态
SELECT vendor_id, last_ingested_date, last_run_id
FROM vendor_ingest_state;
```

## 🔧 常见问题

### Q1: 数据库连接失败

**错误**：`psycopg2.OperationalError: could not connect to server`

**解决**：
```bash
# 检查数据库是否运行
docker ps | grep postgres  # 如果用 Docker
pg_isready  # 如果用本地 PostgreSQL

# 检查 .env 配置
cat backend/.env | grep DB_

# 重启数据库
docker compose -f docker-compose.local.yml restart postgres
```

### Q2: 端口被占用

**错误**：`Address already in use: 8000` 或 `5173`

**解决**：
```bash
# 方式 A: 杀掉占用端口的进程
lsof -ti:8000 | xargs kill -9  # Mac/Linux
netstat -ano | findstr :8000   # Windows

# 方式 B: 换个端口
uvicorn main:app --port 8001  # 后端
npm run dev -- --port 5174    # 前端
```

### Q3: Playwright 安装失败

**错误**：`playwright install` 很慢或失败

**解决**：
```bash
# 设置镜像（国内用户）
export PLAYWRIGHT_DOWNLOAD_HOST=https://npmmirror.com/mirrors/playwright/

# 重新安装
python -m playwright install chromium
```

### Q4: 某个供应商拉取失败

**检查步骤**：

1. **确认凭据正确**
   ```bash
   cat backend/.env | grep VENDOR_NAME
   ```

2. **查看日志**
   ```bash
   # 查看后端日志
   tail -f backend/data/logs/scheduler.log
   ```

3. **手动测试**
   ```python
   # 进入 Python shell
   cd backend
   python
   
   >>> from vendors import get_vendor
   >>> from bigmodel_client import fetch_vendor_usage
   >>> vendor = get_vendor('bigmodel')
   >>> result = fetch_vendor_usage(vendor, '2026-07-01T00:00:00+08:00', '2026-07-12T23:59:59+08:00')
   >>> print(result)
   ```

4. **检查 session 文件**（需要登录的供应商）
   ```bash
   ls -la backend/config/sessions/
   cat backend/config/sessions/bigmodel_cn.json
   ```

### Q5: 前端显示空白

**检查步骤**：

1. **确认后端运行**
   ```bash
   curl http://localhost:8000/api/vendors
   ```

2. **检查前端配置**
   ```bash
   # 编辑 frontend/.env 或 frontend/vite.config.js
   # 确保 API 地址正确
   VITE_API_BASE_URL=http://localhost:8000
   ```

3. **清除缓存重启**
   ```bash
   cd frontend
   rm -rf node_modules/.vite
   npm run dev
   ```

### Q6: 数据不更新

**检查步骤**：

1. **查看 run 历史**
   ```bash
   curl http://localhost:8000/api/ingest/runs?vendor_id=bigmodel&limit=5
   ```

2. **查看 state**
   ```bash
   curl http://localhost:8000/api/ingest/state | jq '.[] | select(.vendor_id=="bigmodel")'
   ```

3. **手动触发**
   ```bash
   curl -X POST http://localhost:8000/api/ingest/vendors/bigmodel/trigger \
     -H "Content-Type: application/json" \
     -d '{"start": "2026-07-12", "end": "2026-07-12"}'
   ```

## 📁 本地项目结构

```
llm_usage_dashboard/
├── backend/
│   ├── .env                    ← 你的配置（不提交 git）
│   ├── main.py                 ← FastAPI 入口
│   ├── *_client.py             ← 各供应商的 client
│   ├── ingest/                 ← 数据入库模块
│   │   ├── adapters/           ← 各供应商的 adapter
│   │   ├── backfill.py         ← 批量回填脚本
│   │   ├── scheduler.py        ← 定时任务
│   │   └── models.py           ← 数据库模型
│   ├── config/
│   │   ├── vendors.json        ← 供应商配置
│   │   └── sessions/           ← 登录 session（自动生成）
│   └── data/
│       ├── logs/               ← 日志文件
│       └── postgres/           ← 数据库数据（如果用 Docker）
├── frontend/
│   ├── src/
│   │   ├── views/              ← 页面组件
│   │   └── components/         ← UI 组件
│   └── package.json
├── docs/                       ← 文档目录
└── docker-compose.local.yml   ← 本地 Docker 配置
```

## 🚫 不要做的事

1. **不要提交 `.env` 文件到 git**
   - 包含你的密钥和密码
   - 已在 `.gitignore` 中

2. **不要提交 `config/sessions/` 目录**
   - 包含登录 session
   - 已在 `.gitignore` 中

3. **不要使用公司的凭据**
   - 使用你自己的供应商账号
   - 避免数据混淆

4. **不要在生产环境用本地配置**
   - `DB_PASSWORD=postgres` 等弱密码仅用于本地开发
   - 生产环境需要强密码

## 🎯 最小配置示例

如果你**只想测试智谱 BigModel**：

```bash
# backend/.env（最小配置）
DB_HOST=localhost

DB_NAME=llm_usage
```

```bash
# 1. 启动数据库
```

### 3. 访问

打开浏览器：http://localhost:5173
